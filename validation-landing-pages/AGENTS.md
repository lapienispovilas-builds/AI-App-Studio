# AI App Studio — Landing Page Instructions

## Goal

Build five simple validation landing pages for mobile app ideas.

## Principles

- Optimize for validation speed, not perfection.
- Keep the implementation simple.
- Use one reusable landing-page component.
- Store each idea's content in configuration data.
- Make every page mobile-first.
- Avoid unnecessary dependencies.
- Do not add authentication, payments, dashboards, or a complex backend.
- Explain meaningful changes in beginner-friendly language.
- Run the project locally and fix errors before declaring the task complete.

## Source documents

Read the briefs inside the `docs` folder before implementing pages:

- `docs/adhd-spending.md`
- `docs/safety-check-in.md`
- `docs/couples-check-in.md`
- `docs/doomscrolling.md`
- `docs/subscription-tracker.md`

Treat those files as the source of truth for:

- target audience;
- value proposition;
- headlines;
- benefits;
- signup questions;
- product mockup content.

Do not invent major product features that are not described in the briefs.

## Landing-page requirements

Each page should contain:

1. Hero headline
2. Short subheadline
3. Three benefits
4. One simple mobile-app mockup
5. Email field
6. Willingness-to-pay question
7. Optional biggest-frustration question
8. Join Early Access button
9. Confirmation state after submission
